# JEDEC fixtures

Real JEDEC files, used as test inputs. Unlike the standard's examples — which are typographically tidy and, in places, [corrupt](../evidence/references.toml) — these are what working tools actually emit.

## Why these files earn their place

**They are the cross-check.** Each carries a `C` fuse checksum that Galette computed with its own implementation, from its own fuse data. deCPLD parses the `L` fields, computes the checksum with code that never saw Galette's, and lands on the same `0x403E` over 2194 fuses. Two independent implementations agreeing on that is what moves the checksum algorithm from "matches the standard's worked example" to `OpenSourceCrossChecked` (SPEC.md §13.1).

That agreement also validates **fuse placement**, not just arithmetic. A checksum that matched while any fuse sat at the wrong index would be a coincidence worth roughly one chance in 65,536.

**They are shaped like real files.** Galette writes each field's terminating `*` at the *start of the following line*, uses lowercase hex digits, and ends with a bare `*` before ETX. All of it is conformant, and none of it looks like the standard's examples. A parser written only against the prose would plausibly reject the lot — so these fixtures are what prove deCPLD reads the real world rather than an idealised version of it.

**The pair isolates one variable.** The two files are the same design differing only in `G0` versus `G1`. Their fuse vectors must come out identical, which confirms the security bit is not being confused with fuse data.

## Adding fixtures

Record provenance and licence in the table above. Prefer files from an implementation that shares no code with deCPLD — a fixture generated by deCPLD itself proves only that it is self-consistent, which is the one thing that was never in doubt.
